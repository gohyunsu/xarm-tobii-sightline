Go / no-go gates

Each gate requires a concrete artifact. A verbal “it should work” is not a pass.

12-week execution path

Measure first, automate last

Calendar weeks are indicative. Exit criteria—not elapsed time—control progression.

Weeks 1–2 · Audit

Freeze the physical and legal starting point

  • Complete G0 inventory sheet with photos and versions
  • Obtain Tobii license/SDK determination
  • Bring xArm up in a low-speed guarded sandbox
  • Measure workcell and candidate camera geometry
  • Draft data-management and ethics documents

Exit: G0–G2 pass/fail recorded with owners.

Weeks 3–4 · Recorder

Capture before adapting

  • Record gaze, camera, controller, xArm, and UI streams
  • Implement shared episode/event identifiers
  • Store calibration, validity, and display geometry
  • Build AOI annotation and audit tools
  • Run end-to-end synchronization test

Exit: 10-minute episode with integrity and residual report.

Weeks 5–6 · Baselines

Build C0, C1, and C2 first

  • Manual-switch interface and event logging
  • Persistent-multiview layout
  • Interpretable geometry risk components
  • Auxiliary-panel hysteresis and override
  • Scripted scene and outcome-scoring tools

Exit: two researchers safely complete every task and recovery path.

Week 7 · Shadow mode

Evaluate gaze policy without changing the screen

  • Audit dynamic AOIs and visibility labels
  • Compute inspection coverage and missingness
  • Review early, late, false, and unstable triggers
  • Verify invalid-gaze fallback
  • Freeze candidate thresholds

Exit: triggers are reproducible without hindsight from outcomes.

Weeks 8–9 · Design pilot

Test C3 and task difficulty

  • Run 6–8 pilot participants after approvals
  • Measure camera churn, surprise, and control reversal
  • Check fault-scoring agreement
  • Estimate outcome variance and condition correlation
  • Simulate power for H3

Exit: G3–G5 passed and preregistration ready.

Weeks 10–12 · Confirmatory study

Run a frozen protocol

  • Balanced Latin-square assignment
  • Live data-quality dashboard without outcome peeking
  • Condition-masked physical-outcome scoring
  • Preregistered mixed-effects analysis
  • Negative results and boundary cases retained

Exit: reproducible report and governed derived-data export.

Team interfaces

Assign responsibility, not just software modules

One person may hold several roles in a small team, but implementation, approval, and analysis responsibilities remain explicit.

Robot and safety

xArm bring-up, workspace/velocity guards, controller, E-stop, props, pre-session checklist, and fault recovery. Has authority to stop a session.

Gaze and interface

Tobii licensing, calibration, validity, dynamic AOIs, C0–C3 rendering, overrides, and the gaze/motion authority boundary.

Data and analysis

Clock mapping, schema, quality report, preregistration, power simulation, mixed models, and reproducible governed export.

Protocol and evidence

Ethics, consent, scene scripts, participant operation, masked scoring, related-work updates, and media provenance.

Separation of duties: the person tuning trigger thresholds should not inspect confirmatory outcomes before the policy is frozen. Physical outcome raters should be masked to condition where the video permits.

Risk register

Manage the failures most likely to invalidate the study

The highest research risks are not headline eye-tracker accuracy. They are permission ambiguity, weak task contrast, asynchronous streams, adaptive-display disturbance, and unsafe integration.

Definition of done

A demo is not the finish line

The work is complete only when another researcher can reconstruct the protocol, implementation decisions, data quality, analysis, and failures.

Research package

  • Preregistered hypotheses, outcomes, contrasts, and exclusions
  • Versioned protocol and task-scene manifest
  • Power simulation and sample-size decision
  • Ethics, license, retention, and release decisions

Technical package

  • C0–C3 display policies and tests
  • Recorder, clock mapping, and residual audit
  • Versioned risk, AOI, and task-graph files
  • Safety, recovery, and failure-handling checklists

Evidence package

  • Quality-controlled Sightline Episodes
  • Condition-masked outcome labels and agreement
  • Reproducible confirmatory and sensitivity analysis
  • Negative results, ablations, limitations, and media provenance
Success criterion: not “the adaptive panel appeared.” Success is a credible causal estimate of whether inspection-aware presentation adds value over geometry-only under defined visibility, operator, and quality conditions.
