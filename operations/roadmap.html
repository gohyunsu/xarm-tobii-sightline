Go / no-go gates

기능 개발보다 먼저 답할 여섯 질문

각 Gate는 통과 증거와 실패 시 경로를 가진다. 팀의 낙관적 판단만으로 체크하지 않는다.

Gate통과 증거실패 시 경로
G0 · InventoryxArm model/SN, gripper, firmware, controller, Tobii SKU, PC/OS, camera 목록을 사진·문서로 확인장비 가정을 모두 provisional로 유지, 구매·대여 결정
G1 · License해당 Tobii SDK/SDLA가 gaze 저장·전송·분석을 허용한다는 서면 근거허가된 Tobii Pro 장비 사용 또는 eye-tracking 요소 제거
G2 · Safety저속 제한, workspace, dead-man, barrier, E-stop, recovery checklist를 독립 점검자가 확인simulation/video-only study로 전환
G3 · Synccamera–gaze–controller–robot end-to-end residual 분포와 dropped-frame reportonline trigger를 끄고 shadow-mode offline 분석
G4 · Task validitysingle view에서 floor가 아니고 always-multi에서 ceiling이 아닌 오류율; high/low occlusion 분리물체·배치·속도·tolerance 재설계
G5 · EthicsIRB/기관 판단, 동의서, 보관·폐기·공개 범위, 철회 절차비인간 기술 파일럿까지만 진행

12-week path

측정 → 기준선 → 적응형 보조 → 검증

일정은 달력보다 Gate 통과 순서가 우선이다. 사람 대상 일정은 윤리·라이선스 승인을 앞당기지 않는다.

1–2주 · Audit

장비·권한·과제 고정

  • G0 inventory sheet
  • Tobii license 확인
  • xArm low-speed sandbox
  • camera 후보와 작업물 도면
  • data management 초안

Exit: G0–G2 통과 여부 문서화.

3–4주 · Recorder

먼저 모두 기록

  • gaze/camera/robot/controller recorder
  • 공통 event ID와 clock mapping
  • calibration/validity UI
  • AOI annotation prototype
  • sync audit script

Exit: 10분 연속 episode 무결성 report.

5–6주 · Baselines

C0·C1·C2 구현

  • manual switch
  • always multi layout
  • geometry risk score
  • view hysteresis/override
  • scripted task scenes

Exit: 연구자 2명이 모든 과제를 안전 완료.

7주 · Shadow mode

gaze 규칙을 화면 없이 검증

  • dynamic AOI quality audit
  • inspection coverage 계산
  • false/late/early trigger review
  • invalid-gaze fallback
  • threshold freeze

Exit: hindsight 없이 trigger가 계산됨.

8–9주 · Technical pilot

C3와 과제 난이도 조정

  • 6–8명 pilot
  • camera churn·surprise 측정
  • 오류 scoring 신뢰도
  • variance/effect estimate
  • power simulation

Exit: G3–G5 및 preregistration draft.

10–12주 · Confirmatory

동결된 protocol 실행

  • Latin-square allocation
  • quality monitoring
  • blinded outcome scoring
  • mixed-effects analysis
  • negative results 포함 보고

Exit: 재현 가능한 report와 de-identified export.

Team interfaces

모듈이 아니라 책임으로 역할 나누기

작은 팀에서는 한 사람이 여러 역할을 맡을 수 있지만 승인·코드·분석 책임은 문서상 분리한다.

Robot & safety

xArm bring-up, workspace/velocity guard, controller, E-stop, recovery. 매 session 시작 checklist 승인.

Gaze & UI

Tobii calibration, validity, AOI, C0–C3 layout, override, gaze/command 권한 분리.

Data & analysis

clock sync, schema, quality report, preregistration, mixed model, reproducible export.

Protocol & evidence

IRB/동의, task script, participant 운영, blinded scoring, 문헌·미디어 provenance.

Risk register

가장 그럴듯한 실패부터 관리

확률과 영향이 모두 큰 위험은 gaze 정확도가 아니라 권한·과제 타당도·자동 화면 변화다.

Definition of done

논문 외에도 남겨야 할 것

성공적인 연구는 멋진 데모가 아니라 다른 사람이 조건·데이터·실패를 재구성할 수 있는 상태다.

Research package

  • preregistered hypotheses/contrasts
  • protocol와 exclusion rules
  • task scene manifest
  • IRB/license decision record

Technical package

  • C0–C3 UI policies
  • recorder와 sync audit
  • risk/AOI version files
  • safety/recovery checklist

Evidence package

  • quality-controlled Episodes
  • reproducible analysis
  • negative/ablation results
  • media provenance와 limitation
