Interaction contract

Define one episode before writing the policy.

The user should always know what the robot thinks the source and destination are, whether it is waiting, why it declined, and when motion can begin. This page fixes that contract so interface, gaze, VLA, control, and evaluation workstreams implement the same task.

01 · Task contract

Freeze the scene, command grammar, and outcome

The first version should avoid open-world robotics. Constrain the workcell enough to measure the interaction while retaining genuine visual ambiguity.

ElementVersion 1 contractLater extension
Source objects3–6 graspable parts from 2–3 similarity families; individually labeled underneath for ground truthunseen instances, transparent items, partial occlusion
Destinationstwo visually distinct trays or bins with fixed safe place posesvariable destination pose or gaze-selected destination
Languageshort grammar: “put this / the [attribute] part in the [color] bin”free speech, Korean/English variants, repair dialogue
Gazescreen-based Tobii on one robot-camera feed; target fixation during reference phrasemultiple views, egocentric gaze, dynamic target change
Robot actiontop grasp, lifted transport, placement, retreat within a fixed bounded workspaceorientation-sensitive insertion or part-level grasp
Activationvisible proposal plus explicit confirm button or spoken confirmationrisk-calibrated low-friction activation after ethics/safety review
Recommended MVP: keep destination language explicit and use gaze only for the source object. This isolates the central hypothesis and prevents one gaze window from ambiguously representing both source and destination.

03 · Interface

One view, one proposal, one clear decision

The interface should support intent communication without becoming a distracting research dashboard. Detailed telemetry belongs in an observer panel or replay tool, not in the operator’s critical path.

Operator panel

  • Large, stable robot-camera image
  • small tracking-quality indicator
  • transcribed command for correction
  • proposed source and destination contours
  • plain-language uncertainty message
  • Confirm, Try Again, Use Click, and Stop controls

Observer panel

  • candidate probabilities and top-two margin
  • gaze mean, covariance, sample validity, and age
  • VLA/adapter version and action proposal
  • xArm mode, joint/TCP state, guard decisions, and faults
  • stream synchronization and frame age
  • event markers and outcome annotation
Avoid a live gaze cursor during normal trials: it can cause the operator to chase the cursor, reveal calibration noise, alter looking behavior, and accidentally turn the task into cursor control. Show the selected object or uncertainty region only after the estimation window closes.

04 · Temporal semantics

Which gaze belongs to “this”?

A continuous gaze stream must be bound to a discrete referring event. The choice of window is part of the method and cannot be changed per trial.

Reference-aligned window

Let \(t_r\) be the timestamp of the deictic/reference phrase identified from push-to-talk or speech alignment. Use a pilot-tuned window \([t_r-\Delta_{\mathrm{pre}},\,t_r+\Delta_{\mathrm{post}}]\), weight samples by validity and recency, and retain the raw stream for sensitivity analysis.

\[\mu_g=\frac{\sum_{i\in\mathcal W}q_i k(t_i-t_r)g_i}{\sum_{i\in\mathcal W}q_i k(t_i-t_r)},\quad \Sigma_g=\Sigma_{\mathrm{samples}}+\Sigma_{\mathrm{calibration}}+\Sigma_{\mathrm{mapping}}.\]

Here \(q_i\) is sample quality and \(k\) is a preregistered temporal kernel. Combining measurement, calibration, and mapping uncertainty prevents artificially narrow confidence.

Push-to-talk MVP

The button defines a clean utterance interval and reduces speech endpoint ambiguity. This is the recommended first implementation.

Keyword alignment

Align gaze around “this,” “that,” or the source noun. Requires reliable timestamped transcription and repair rules.

Continuous intent

Online dynamic gaze conditioning is a separate research problem already close to Gaze2Act; defer it beyond the static pick-and-place study.

05 · Clarification policy

Different uncertainty needs different repair

“Try again” is not enough. The system should distinguish missing gaze, broad gaze, competing candidates, unresolved language, and invalid destinations.

Good abstention is a success outcome: score whether the system declined when it should, not only how often it executed. A lower wrong-pick rate achieved by refusing every difficult trial is also not useful, so coverage and task completion must be reported together.

06 · Recovery

Failures end in known states

The physical demo should be rehearsed around failures, not only the nominal path. Each recovery must preserve traceability and never silently resume an old target.

Lost gaze

Discard the incomplete reference window, return to Ready, and require a new utterance after tracking recovers.

Bad transcript

Let the user edit or repeat the instruction. Do not fuse corrected text with an old gaze window unless the protocol explicitly permits it.

Failed grasp

Stop or retreat to a safe observation pose, label the mechanical failure, and start a new attempt with a new episode ID.

Fault / E-stop

Freeze the episode, invalidate pending commands, require experimenter reset, re-home/check xArm, and run the restart checklist.

Interaction precedent

Borrow the useful distinction, not the novelty claim

Gaze2Act’s visual explanation—language says what, gaze says which object or part—closely matches the interaction premise. GazePick differentiates through screen-based uncertainty, abstention, explicit confirmation, and xArm-specific ablations.

07 · Demonstration script

Show the claim in three minutes

A short demo should expose both value and limits. A flawless single nominal rollout cannot demonstrate uncertainty handling.

Establish the problem

Show three similar parts and issue a language-only deictic command. Display multiple plausible candidates without moving.

Resolve with gaze

Look at one part, repeat the destination, show the posterior and selected contour, confirm, and execute a correct pick-and-place.

Demonstrate abstention

Look between two candidates or step outside the tracking box. The system explains the issue and remains stationary.

Recover

Recalibrate or re-look, confirm the corrected target, and complete the task. Show the synchronized event replay.

Close with evidence

Present matched condition results: wrong-pick rate, referent time, completion, abstention, and the adapted-versus-frozen comparison.
